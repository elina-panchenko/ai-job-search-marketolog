Ты формируешь пул кейсов кандидата из его ответов на анкеты и вопросы HR.
Сырьё — только МОИ ответы (не описания вакансий и не вопросы HR — они лишь
контекст). Цель — превратить разрозненные ответы в полноценные кейсы в
`facts/cases.md`, ничего не выдумывая.

## Источник для разбора

Бери мои ответы из одного из двух мест:
1. **Текст, переданный вместе с командой** (ниже) — если он есть, разбирай его.
2. **Текущая беседа** — если к команде ничего не передано, возьми мои ответы на
   анкету/вопросы, которые уже прозвучали в этом диалоге.

Переданный текст (может быть пустым):
$ARGUMENTS

Если источник определить не получается (ни текста, ни ответов в беседе) — спроси,
по какой компании/анкете разбираем, и **не начинай вслепую**.

## Алгоритм

1. **Выдели кандидатов в кейсы.** Каждый самостоятельный проект/результат из моих
   ответов — отдельный кейс (напр. «реактивация базы», «запуск флагманской
   программы», «ROMI из минуса в плюс»). Один ответ может дать несколько кейсов;
   несколько ответов — дополнять один кейс.

2. **По каждому кандидату определи — новый или уже есть.** Сверься с `facts/cases.md`
   (если файла ещё нет — считаем, что все кейсы новые, файл создадим при первой записи).
   - **Новый кейс** → собери полноценный кейс в формате ниже. Обогати подачу:
     разверни «Было / Что сделала / Стало», убери воду, усиль формулировки — но
     **факты и цифры бери только** из моих ответов и `facts/experience.md`. Если
     для полного кейса не хватает данных (что было ДО, конкретная цифра, срок,
     инструмент, роль) — **задай мне уточняющие вопросы**, а не придумывай.
   - **Кейс уже есть** → идентифицируй его. Проверь, есть ли в этих ответах новое:
     дополняющая цифра, деталь, новый ракурс подачи. Если есть — подготовь
     дополнение и **покажи мне «было → стало» по самому кейсу** (что в кейсе сейчас
     и как он станет выглядеть после дополнения).

3. **Утверждение перед записью.** Ничего не пишу в `facts/cases.md` без моего «ок».
   По каждому кейсу отдельно:
   - покажи черновик (для нового) или дифф «было → стало» (для дополнения);
   - задай уточняющие вопросы, если они есть;
   - дождись моих правок и подтверждения;
   - только после этого мержи в `facts/cases.md`.
   Идём по кейсам по очереди — не сваливай всё в одну кучу.

## Формат кейса в facts/cases.md

```
### <Короткое название кейса> — <проект / компания>
- **Контекст / роль:** где и в какой роли
- **Было:** ситуация/проблема до меня (цифра, если есть)
- **Что сделала:** конкретные действия, инструменты, механики
- **Стало (результат):** измеримый результат — цифры из facts/experience.md
- **Чем полезно под роль:** под какой акцент вакансии подаётся
- **Источник:** откуда вытащено (напр. «анкета BAND, вопрос 5»)
```

Если файла `facts/cases.md` ещё нет — создай его с заголовком и краткой шапкой
(что это пул фактических кейсов, цифры сверяются с `experience.md`), затем добавляй кейсы.

## Правила

- Не выдумывай факты, цифры, сроки, результаты. Нет данных — вопрос мне или пусто.
- Цифры сверяй с `facts/experience.md`; если цифра в ответе расходится с фактами —
  не молчи, покажи расхождение.
- Даты — `ГГГГ-ММ-ДД`. В конце файла обнови строку последнего обновления, если она есть.
- В конце коротко отчитайся: какие кейсы добавлены, какие дополнены, какие
  отложены до твоих ответов на уточняющие вопросы.
